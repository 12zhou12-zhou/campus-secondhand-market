# 架构与数据模型说明

## 1. 系统环境关系

系统通过浏览器连接买家、卖家和平台管理员，由服务端执行认证、授权、业务校验和数据保存。第一版使用 SQLite；除可选密码重置邮件外，不依赖学校统一认证或其他外部业务系统。

```
浏览器（买家 / 卖家 / 管理员）
        │  HTTPS / HTTP
        ▼
   Django 服务端
   ├── 认证与会话（accounts）
   ├── 业务校验与授权
   ├── 商品 / 沟通 / 评价 / 通知 / 统计（items、chat 等）
   └── ORM 数据访问
        │
        ▼
      SQLite 数据库 + 本地附件存储
```

## 2. 模块划分

| 模块 | 职责 |
| --- | --- |
| accounts | 注册、登录、退出、找回邮箱、密码重置、个人资料与身份审核 |
| items | 商品创建、列表、详情、补充说明、成交标记、下架、评价 |
| locations | 商品分类、成色标准、交易方式的维护与停用 |
| chat | P1 商品内文字消息，终止状态后只读 |
| admin | Django 管理入口或维护工具，仅授权维护人员使用 |
| core | 公共配置、基础模型、公共工具与权限校验 |

## 3. 领域模型（ER 概要）

### 3.1 账号领域

- **用户（User）**：账号、密码散列、姓名、手机号、找回邮箱、账号状态、审核状态。
- **卖家资料**：昵称、学号或手机号、联系方式、所属学院或年级、实名认证状态、审核材料。
- **买家资料**：昵称、学号或手机号、联系方式、所属学院或年级。
- **审核记录**：审核人、审核时间、审核结果（通过 / 待补充 / 未通过）、原因说明。

### 3.2 商品领域

- **商品（Item）**：商品编号（SP+YYYYMMDD+当日4位流水号）、标题、描述、价格、分类、成色、交易方式、当前卖家、状态、快照、提交时间。
- **商品图片**：所属商品、文件标识、上传人、上传时间；鉴权访问，不提供公开直链。
- **咨询 / 聊天消息**：所属商品、发送人、接收人、内容、发送时间；终止状态后只读。
- **成交记录**：成交说明、确认人、确认时间。
- **下架申请**：下架原因、申请时间、审核人、审核结果与说明。
- **评价**：所属商品、评价人、星级、评语、提交时间；管理员可隐藏不当评语并留痕。
- **通知**：接收人、事件类型、内容、时间、已读状态。

### 3.3 关键约束

- 账号、非空手机号、非空邮箱、商品编号需唯一约束。
- 商品状态、创建时间、提交人、当前卖家字段建立索引。
- 商品发布时保存资料快照，不随基础资料修改而变化。
- 审核、下架、推荐位调整、成交确认、评价隐藏等操作写入不可覆盖的业务审计记录。

## 4. 商品状态流转

```
在售 ──买家咨询──▶ 咨询中 ──卖家标记成交──▶ 待买家确认
  │                  │                        ├──买家确认──▶ 已成交
  │                  │                        └──反馈未成交──▶ 咨询中
  ├──主动下架──▶ 已下架
  └──管理员违规下架──▶ 违规下架

咨询中 ──申请下架──▶ 下架申请待审核（附加标记，主状态不变）
                          ├──批准──▶ 已下架
                          └──驳回──▶ 恢复咨询中
```

终止状态：已成交、已下架、违规下架，不再进入正常交易流程。
