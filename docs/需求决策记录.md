# 关键需求决策记录（ADR）

> 记录影响范围较大、后续可能被追问依据的需求决策。每条决策包含背景、方案、结论与影响。

## ADR-001 第一版限定校内单校区 Web 使用

- **背景**：项目为课程阶段交付，用户规模与部署资源有限。
- **决策**：第一版仅面向校内单校区学生，提供浏览器访问的 Web 页面；不设计跨校/跨校区部署，移动端专项适配不列入 P0。
- **影响**：身份资料由管理员人工核验；不接入统一身份认证；移动端只要求不出现严重布局问题。

## ADR-002 商品编号规则

- **背景**：商品需要唯一、可读、便于检索的编号。
- **决策**：编号格式为 `SP+YYYYMMDD+当日4位流水号`，例如 `SP202611050001`，由服务端在事务内生成。
- **影响**：号段耗尽或生成失败时明确报错，不留半成品；编号写入唯一约束。

## ADR-003 成交必须买卖双方确认

- **背景**：避免商品被单方面结束交易，减少争议。
- **决策**：卖家标记成交后进入“待买家确认”；买家确认已成交才进入已成交，反馈未成交须填原因并退回咨询中。管理员不代替确认，系统不自动完成。
- **影响**：状态机包含待买家确认；待确认 48 小时后触发催办提醒。

## ADR-004 终止状态只读

- **背景**：保留完整交易记录，防止事后篡改。
- **决策**：已成交、已下架、违规下架为终止状态，历史记录只读；终止后聊天不可发送新消息。
- **影响**：权限与状态校验集中实现，模板中不残留可执行按钮。

## ADR-005 敏感资料最小权限展示

- **背景**：手机号、邮箱、学院年级、审核材料、图片和聊天属于敏感信息。
- **决策**：按角色与对象归属控制可见范围；审核材料仅本人和管理员可访问；商品图片通过鉴权文件接口返回，不提供公开直链。
- **影响**：越权访问拒绝且不泄露附件；文件安全需校验扩展名、MIME 与实际内容。

## ADR-006 技术栈沿用 Python + Django + SQLite

- **背景**：第一版为小规模课程项目，需降低部署与复现成本。
- **决策**：使用 Python 3.12、Django 5.2、SQLite，服务端渲染为主；后续并发或数据量扩大时再评估独立数据库与共享缓存。
- **影响**：备份需使用一致性备份方式，不得直接复制写入中的 SQLite 文件。

## ADR-007 优先级划分 P0 / P1 / P2

- **背景**：阶段交付需要明确验收阻断项。
- **决策**：P0 为最小可运行交易闭环所必需；P1 为第一版增强能力；P2 为范围外后续扩展。
- **影响**：P0 必须全部通过才可判定最小可运行版本完成；未完成 P1 须记录为已知差距并关联后续 Issue。
